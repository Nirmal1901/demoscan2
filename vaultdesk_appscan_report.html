How to fix

SQL Injection

Cause

User-controlled data is concatenated into an SQL statement, so its content can change the meaning of the query. This includes values that were stored earlier and are read back later.

Fix Recommendations

Use parameterized queries (placeholders) for every value, including values read back from the database. Identifiers such as table names cannot be parameterized: map them from a fixed allow-list.

Server-Side Request Forgery

Cause

The application makes an outbound HTTP request to a URL that is partly controlled by the user, so it can be pointed at internal services or cloud metadata endpoints.

Fix Recommendations

Parse the URL and compare the scheme and the exact hostname against an allow-list; do not use string prefix checks. Resolve the host and reject private and link-local addresses. Disable redirects.

Path Traversal

Cause

A file path is built from user input, and the input is decoded or normalized after it was validated, so encoded sequences can climb out of the intended directory.

Fix Recommendations

Decode first, then validate. Resolve the final path with realpath and verify it is inside the base directory. Prefer serving files by an opaque ID.

Insecure Deserialization

Cause

Data from the request is deserialized with a format that can execute code (pickle). A signature check does not help if the signing key is guessable or hard-coded.

Fix Recommendations

Do not deserialize untrusted data with pickle. Use a data-only format such as JSON with schema validation. Never fall back to a hard-coded signing key.

Improper Verification of Cryptographic Signature

Cause

A token is accepted without a valid signature because the verifier trusts the algorithm and issuer claims inside the token itself.

Fix Recommendations

Accept only the algorithms you issue (pin HS256) and always verify the signature. Never accept unsigned tokens based on claims the token carries.

Authorization Bypass Through User-Controlled Key

Cause

A record is loaded and modified using an identifier from the request without checking that the caller owns it, and request fields can overwrite ownership attributes.

Fix Recommendations

Check that the record belongs to the caller (or the caller is privileged) before reading or changing it. Restrict updatable fields per role; ownership fields must not be client-editable.

Open Redirect

Cause

A redirect target comes from the request and the validation can be bypassed with URL forms that browsers interpret differently from the parser.

Fix Recommendations

Only redirect to paths from a fixed allow-list, or require the target to start with a single / and contain no backslash, then re-parse the result.

Cross-Site Scripting

Cause

Data is written into a response without output encoding.

Fix Recommendations

Encode output for its context and make sure the response content type is correct.
